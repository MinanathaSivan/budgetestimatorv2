1.1 Connectivity with One Account end point

As One Account is reachable only on internet, application server most likely needs to rely on a proxy to reach Oneaccount endpoints. Below some usefull informations and links to help you with the set up depending on your application location (If none of those 2 solutions worked please reach out to us)  : 

OpenPaaS Hosted application :

Need to use a proxy or egress transport  within its DatacCenter infrastructure to reach OAuth's end points , refer to  Accessing public services through egress proxies & routers for more details about egress proxies set up. 
MPI Hosted application:

Outbound Internet access must go via the onPrem Proxy, please refer to Entity Hub Firewall - Managed Public IaaS - Confluence by AXA GO for more details .


For some "old" applications running in CORE IT for example, application servers might not have internet access - same for locked-down cloud networks.

A direct connection to AWS should also work if all AWS subnets are well opened (see also AWS IP address ranges - Amazon Virtual Private Cloud). 

Note : Opening flows to AWS subnets to reach Oneaccount endpoints is not recommended and must be used ONLY if your application can not rely on a proxy (due to a technical limitation)

Sample header
To obtain the header from that token, extract the first part - before the first . (period) - and decode it using base64url. The result must be a valid JSON object. 

The header for a One Account's access token :





From the config document you have the jwks_uri where to find the corresponding key id to check the signature : 




This header indicates that this particular token is signed using the RS256 alg (RSA with SHA256 digest), and that its signature must be validated with the public key that has the kid (Key Id) 2Qx2tMuI8TXJzd16eq4NQj1V2hU

IMPORTANT SECURITY NOTICE: you must check that the alg value is RS256 and you must actually use that RS256 algorithm to validate the signature, instead of trusting the value that appears in the header. Not doing so is a critical security flaw, see https://auth0.com/blog/critical-vulnerabilities-in-json-web-token-libraries/
