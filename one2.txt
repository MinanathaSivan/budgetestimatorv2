Best Practices


Client IDs (including secrets and relevant details) 
A client ID / client secret is delivered for 1 application instance and should not be shared with others! 
JWKS  Caching
in general java web keys should not be cached - as the providing authentication/authorization platform is supposed to rotate them as needed to increase security (some endpoints even signal this by no-cache,no-store response header
if an application decides to cache those for performance improvements on client side and reduction of calls toward the oauth server
then those caches should be checked and updated in regular interval eg. every 12 hours.
then a robust signature check must be implemented: e.g. on x failure signature checks the application needs to refresh its jwks cache even before its regular scheduled updates, x to be defined by the application owner but values between 1-5 seem reasonable
